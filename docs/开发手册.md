# FileMaster 2.0 开发手册

> 本手册基于现有 file-master 项目（PySide6 + SQLite 桌面文件管家）的升级改造计划编写。
> 原则：**改造不重写**——保留扫描、去重、缩略图、标签、打包等已有资产，重点做架构解耦与功能升级。

---

## 一、产品定位与功能总览

### 1.1 定位

单机 Windows 桌面应用，面向**媒体文件（图片/视频/音频）、文档、压缩包**的本地索引式管理：
不搬家、可打标、能检索、可去重、敏感文件可加密，未来支持手机局域网访问。

### 1.2 功能清单（目标态）

| 模块 | 功能 | 现状 |
|---|---|---|
| 扫描索引 | 目录扫描、增量更新、白名单过滤、MD5 按需补算 | 已有，需改造 |
| 分类识别 | 类型自动分类、EXIF/时长/分辨率元数据、自动规则标签 | 部分，需增强 |
| 标签系统 | 手动标签 CRUD、批量打标、AND/OR 分组组合检索 | 部分，需增强 |
| 去重清理 | MD5 精确去重、感知哈希相似聚类、回收站安全删除 | 部分，需增强 |
| 预览 | 异步缩略图、图片缩放、视频调用播放器、文档首页预览 | 已有，需补文档 |
| 界面框架 | 菜单栏 + 分组工具栏 + 可停靠面板系统（任意面板可浮动为独立窗口、可停靠展示区上下左右、可合并为页签）、暗色主题、布局记忆 | 改造（重点） |
| 安全 | 启动密码、Vault 文件加密区、加密备份导出 | 新增 |
| 整合导出 | 归集区（硬链接收拢）、导出视图、CSV 报表 | 新增 |
| 设置中心 | 修改数据目录（含自动迁移）、扫描路径管理、缓存清理 | 新增 |
| 手机服务 | FastAPI 局域网浏览/打标（桌面库为权威） | 预留（后期） |
| 打包 | PyInstaller exe，可选 Inno Setup 安装器 | 已有，需更新 |

### 1.3 明确不做

- 多用户体系（单机单用户 + 启动锁）
- 文件内容全文检索（列入远期 TODO）
- 大模型/CLIP 语义识别（本地 CPU 与体积不允许，留接口）

## 二、总体架构

### 2.1 分层规则

```
ui (PySide6) ──┐
               ├──> core (纯 Python 业务层，禁止 import Qt) ──> db (SQLite)
server (FastAPI) ┘（M6 预留宿主）
```

硬性规则：

1. `core` 与 `db` 不允许出现任何 `PySide6` import；后台任务用 `threading`，Qt 侧通过信号桥接收进度
2. UI 层只做展示与信号转发，所有业务调用走 `core` 的 Service，禁止 UI 直接执行 SQL
3. 数据在层间用 `dataclass`/`Pydantic` 模型传递，禁止裸 dict 跨层
4. 后台任务与 UI 共享一个 `AppSignals`（Qt Signal）桥，core 通过回调上报进度，不感知 Qt

## 三、技术栈

| 用途 | 选型 | 说明 |
|---|---|---|
| GUI | PySide6 >= 6.7 | 现有栈，Python 3.13 兼容 |

| 加密 | cryptography | AES-256-GCM + argon2-cffi |
| 压缩包 | 内置 zipfile + py7zr | 清单预览；rarfile 可选（需 unrar.exe） |
| 手机服务（预留） | fastapi + uvicorn | M6 |

| 打包 | PyInstaller（onedir）+ 可选 Inno Setup | 现有 spec 基础上更新 |

## 四、数据库设计

### 4.1 现状（v1）

```sql
files(id, path UNIQUE, name, size, modified_time, md5, added_time, thumbnail_path)
tags(id, tag_name UNIQUE)
file_tags(id, file_id, tag_id)
settings(key, value)
```

### 4.2 目标（v2，通过迁移达成）

```sql
-- 迁移版本控制
PRAGMA user_version;            -- 用原生机制，替代自建 schema_version 表

-- files 增列（ALTER TABLE）
ALTER TABLE files ADD COLUMN file_type TEXT DEFAULT 'other';   -- image/video/audio/document/archive/other
ALTER TABLE files ADD COLUMN md5_state INTEGER DEFAULT 0;      -- 0未算 1已算 2计算中
ALTER TABLE files ADD COLUMN missing INTEGER DEFAULT 0;        -- 扫描时发现文件已不在原位置

-- 媒体元数据（一对一）
CREATE TABLE file_meta (
  file_id INTEGER PRIMARY KEY REFERENCES files(id) ON DELETE CASCADE,
  width INTEGER, height INTEGER,
  duration_sec REAL,
  page_count INTEGER,
  shot_time TEXT,               -- EXIF 拍摄时间 (ISO8601)
  camera TEXT,
  extra_json TEXT               -- 其他低频元数据
);
CREATE INDEX idx_meta_shot_time ON file_meta(shot_time);

-- 标签增强
ALTER TABLE tags ADD COLUMN color TEXT;
ALTER TABLE tags ADD COLUMN is_auto INTEGER DEFAULT 0;          -- 自动规则产生的标签
ALTER TABLE file_tags ADD COLUMN source TEXT DEFAULT 'manual';  -- manual/auto

-- 自动打标规则
CREATE TABLE auto_rules (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  name TEXT NOT NULL,
  match_kind TEXT NOT NULL,     -- ext / dir / meta
  pattern TEXT NOT NULL,        -- 如 'jpg,png' 或目录前缀
  tag_id INTEGER NOT NULL REFERENCES tags(id) ON DELETE CASCADE,
  enabled INTEGER DEFAULT 1
);

-- Vault 加密区
CREATE TABLE vault_items (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  original_path TEXT NOT NULL,          -- 加密前位置（仅记录，不作为访问路径）
  enc_path TEXT NOT NULL,               -- vault 目录内密文文件
  enc_size INTEGER NOT NULL,
  orig_size INTEGER NOT NULL,
  wrapped_dek BLOB NOT NULL,            -- 被主密码派生密钥包裹的文件密钥
  nonce BLOB NOT NULL,                  -- AES-GCM nonce
  added_time REAL NOT NULL
);

-- 归集区记录
CREATE TABLE consolidated_links (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  file_id INTEGER NOT NULL REFERENCES files(id) ON DELETE CASCADE,
  link_path TEXT NOT NULL UNIQUE,       -- 归集区内的硬链接路径
  created_time REAL NOT NULL
);
```

### 4.3 迁移机制

- `db/migrations/` 按序号存放 SQL 文件；启动时比对 `PRAGMA user_version`，逐个执行未应用的迁移（事务包裹 + 执行后更新版本号）
- 迁移前自动做一次 `filemaster.db.bak-{version}` 备份
- SQLite 不支持部分 `ALTER` 操作时，采用"建新表→拷数据→改名"的十二步流程

### 4.4 SQLite 并发约定

- 连接策略：每线程独立连接（`threading.local`），`check_same_thread=False` 不使用
- `PRAGMA journal_mode=WAL; PRAGMA busy_timeout=5000; PRAGMA foreign_keys=ON;`
- 写入统一走 DAO，短事务，禁止长事务跨 UI 事件

## 五、核心模块设计

### 5.1 数据目录管理（含迁移）★

#### 路径解析链（config.py 启动时按序判定）

1. 命令行参数 `--data-dir <path>`（调试用）
2. 环境变量 `FILEMASTER_DATA_DIR`
3. 便携标记：exe 同目录存在 `portable.flag` → 使用 `<exe目录>/data`
4. 指针文件：`%APPDATA%\FileMaster\data_location.txt` 内容为实际数据目录（一行绝对路径）
5. 默认：`%APPDATA%\FileMaster`

> 自举说明：第 4 层解决"数据目录搬走了，程序怎么找到它"的问题——无论数据目录改到哪里，指针文件永远留在默认位置，且永不迁移。

#### 数据目录内容

```
<data_dir>/
├── filemaster.db          # 主库
├── thumbnails/            # 缩略图（以 md5 命名）
├── vault/                 # 加密文件密文存储
├── backups/               # 自动备份 / 加密导出
└── logs/filemaster.log    # 日志
```

#### 目录变更 + 迁移流程（设置中心触发）

```
选择新目录
  → 预检查：可写权限、剩余空间 ≥ 现用数据大小 × 1.2、目标不在现目录内部
  → 暂停后台任务（扫描/缩略图线程置停，等待退出）
  → 关闭全部 DAO 连接
  → db 迁移：sqlite3.Connection.backup() 在线一致性复制（兼容 WAL）
  → 文件迁移：thumbnails/ 与 vault/ 逐文件复制（先临时名，成功后原子改名）
  → 校验：新库 PRAGMA integrity_check；文件/标签计数与旧库一致
  → 写指针文件 data_location.txt；写新目录 marker（版本号）
  → 提示重启应用；旧目录保留原样（UI 提供"清理旧目录"入口，二次确认后才删除）
失败任意一步 → 回滚：删除新目录半成品，恢复连接与后台任务，指针不变
```

验收要求：迁移过程中 kill 进程，重启后旧目录数据完好可用。

### 5.2 扫描与索引

- 保留现有增量逻辑（size + mtime 判重）；**MD5 不在扫描时全量计算**，改为：
  - 扫描只登记 `md5_state=0`
  - 去重面板/查询需要时，后台线程池（`concurrent.futures`，默认 2 workers）按需补算并更新
- 白名单收窄：图片/视频/音频/文档/压缩包扩展名常量表（`core/classifier.py` 统一定义，扫描与分类共用）
- `missing=1` 标记：增量扫描时发现原路径不存在 → 标记而非删除；UI 显示"已失联"，提供批量清理索引入口
- 进度上报：`scanner.run(callback)`，Qt 桥接层把 callback 转成 Signal

### 5.3 分类与智能识别（三级）

| 级别 | 内容 | 触发时机 |
|---|---|---|
| L1 规则 | 扩展名→大类；`auto_rules` 表驱动的目录/扩展名规则标签 | 扫描入库时 |
| L2 元数据 | EXIF（拍摄时间/相机）、视频时长分辨率（ffprobe）、音频时长（mutagen）、PDF 页数（PyMuPDF） | 扫描后低优先级队列 |
| L3 内容 | imagehash 感知哈希（phash/dhash 8字节）存入 `file_meta.extra_json` | 仅图片，后台空闲时 |

- 元数据提取幂等：已提取且 mtime 未变则跳过
- 自动标签与手动标签通过 `file_tags.source` 区分；规则停用不回溯删除，提供"重建自动标签"按钮

### 5.4 标签与 DSL 检索

- 现有 AND 组合（EXISTS）保留为快路径
- 新增分组 DSL，前端结构：

```json
{
  "op": "OR",
  "groups": [
    {"op": "AND", "tagIds": [1, 2]},
    {"op": "AND", "tagIds": [3]}
  ]
}
```

- 编译规则：每组编译为一组 `EXISTS` 子查询（组内 AND），组间 `OR` 连接；Pydantic 校验深度（≤3 层）与标签数（≤32）
- UI：条件构造器对话框（左侧标签多选 → 加入条件组 → 组间"且/或"切换）
- golden test：固定语料库上对 DSL→SQL 的行为做断言测试

### 5.5 去重与相似聚类

- MD5 精确去重：沿用现有分组 + "保留首个删除其余"
- 相似聚类：按 phash 汉明距离 ≤ 8 分组（内存中并查集聚类，图规模为图片量级，可接受）；仅提示，不自动删除
- 删除一律走 send2trash；"仅删索引"选项保留

### 5.6 安全（启动锁 / Vault / 备份加密）

- **启动锁**：首启设置主密码；argon2id 哈希存 `settings` 表；启动弹密码框，连续错误 5 次锁定 60 秒。支持"记住本机（Windows DPAPI 包装会话密钥）"可选项
- **Vault**：
  - 主密码 → argon2id 派生 KEK；每文件随机 32B DEK，AES-256-GCM 加密文件体，DEK 用 KEK wrap 后与 nonce 一并入库
  - 入库流程：选文件 → 加密写入 `vault/`（临时名→原子改名）→ 删原文件（send2trash）→ 登记 `vault_items`，`files` 表原记录移除或标记
  - 解锁态：应用内预览解密到内存；"导出明文"写临时目录并提示用后即焚
  - 修改主密码：重新 wrap 全部 DEK（不重加密文件体，秒级完成）
- **备份加密**：一键导出 `filemaster.db` 的加密副本（SQLCipher 不可靠，改为 Fernet 加密的库文件快照 + 密码校验头）

### 5.7 归集区与导出

- 归集结构：`<归集目标>/图片/2025/xxx.jpg`（按大类/拍摄年月自动组织）
- 硬链接实现：`os.link`（同卷 NTFS 免权限）；跨卷/失败自动回退 `shutil.copy2` 并在记录中标注
- 记录于 `consolidated_links`；源文件被移动后提供"修复链接"操作
- 导出视图：只读浏览入口（打开所在文件夹按钮）；CSV 报表：当前筛选结果导出

### 5.8 局域网手机服务（M6，预留）

- FastAPI 复用 core：只读浏览/搜索/缩略图 + 打标回写
- 同步模型：**桌面库为唯一权威**，手机为瘦客户端；不做双向合并
- 安全：首次启用生成配对码，服务仅监听局域网地址，token 会话

### 5.9 设置中心 UI（新增，模态对话框）

- 数据目录：显示当前路径 + 占用统计；"更改目录"按钮触发 5.1 迁移向导（含进度条与回滚提示）
- 扫描路径管理：增删监控根目录、默认白名单
- 安全：设置/修改主密码、Vault 使用统计、备份导出
- 缓存维护：缩略图占用统计与清理、失联文件清理、数据库 VACUUM

## 六、UI 框架与界面改造（重点）

> 目标布局对照参考图（Visual Components 风格）：**顶部菜单栏 → 分组工具栏 → 中央展示区 + 四周可停靠面板**，暗色主题。
> 技术基座：Qt 原生 `QDockWidget` 停靠体系，浮动/拖靠/合并页签均为框架能力，无需自研拖拽。

### 6.1 主窗口骨架

```
QMainWindow
├── QMenuBar        文件 / 视图 / 工具 / 标签 / 去重 / 设置 / 帮助
├── QToolBar[]      分组图标工具栏（分组间竖线分隔）：检索、视图切换、打标、去重、导入导出、安全、设置
│                   —— 工具栏本身可拖动重排 / 可在菜单中隐藏
├── 中央部件        文件展示区（网格视图 / 列表视图切换；唯一中央部件，不可关闭、不可停靠）
└── QStatusBar      选中统计（N 项 / 总大小）、后台任务进度、库文件总数
```

- `QMainWindow.setDockOptions(AnimatedDrops | AllowNestedDocks | AllowTabbedDocks)`：
  面板可拖到展示区**上下左右**任意边缘停靠、可互相**合并为页签**、可**嵌套分割**
- 面板标题栏按钮（自定义 title bar widget）：**浮动（双击标题切换独立窗口）/ 钉住 / 最大化 / 关闭**

### 6.2 面板系统（插件化）

- 基类 `PanelBase(QDockWidget)`：
  - 强制 `objectName`（布局持久化的 key）
  - 统一标题栏与样式；内容区为任意 QWidget
  - 面板间通信只经信号（Qt Signal）与 core 服务，不直接互引
- 注册表 `registry.py`：`PANEL_REGISTRY: id → (工厂函数, 默认停靠区, 菜单文案, 可选快捷键)`
  - "视图"菜单根据注册表**自动生成**面板开关列表；被关闭的面板从菜单重新打开
  - 新增功能面板 = 写一个类 + 注册一行，主窗口代码零改动

### 6.3 面板清单与默认布局

| 面板 | 默认位置 | 内容 |
|---|---|---|
| 文件展示区 | 中央（不可关） | 网格/列表双模式、类型下拉、失联标记、多选 |

## 九、风险与对策

| 风险 | 对策 |
|---|---|
| M0 重构面广，易引入回归 | 先补冒烟测试再动手；每完成一个 service 迁移即手动验收一次 |
| 面板迁移与解耦耦合（UI 重写涉及全部面板） | M1 只搭框架 + 迁移现有四个面板，不做新功能；每个面板迁移后独立验收 |
| SQLite 多线程写冲突 | 每线程连接 + WAL + busy_timeout；写操作集中到短事务 |
| 大库缩略图/迁移耗时长 | 后台线程 + 进度上报；迁移支持断点（文件级跳过已存在） |
| ffmpeg 二进制体积 | PyInstaller 打包 onedir 而非 onefile；spec 中显式收集 |
| Vault 密码遗忘 | 明确不可找回（无后门）；导出加密备份时强提示 |
| 硬链接语义误用（编辑归集区文件影响原文件） | 归集区只读定位；UI 明示"链接共享内容"，提供复制模式选项 |
| pillow-heif/PyMuPDF 许可证 | AGPL：PyMuPDF 仅本机自用不分发源码可接受；如介意换 pypdfium2 |
